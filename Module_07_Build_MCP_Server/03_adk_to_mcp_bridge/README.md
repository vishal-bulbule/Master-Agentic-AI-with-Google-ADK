# 03: ADK Tool to MCP Server Bridge

## What this shows

An existing ADK `FunctionTool` published as an MCP server without rewriting
it. `adk_to_mcp_tool_type(tool)` converts the ADK declaration into an MCP
`Tool`, and the `tools/call` handler runs the tool through
`FunctionTool.run_async`, the same call path the ADK runtime uses. The same
function can then be used in process as an ADK tool inside an agent, and over
stdio or HTTP as an MCP tool by other hosts (Claude Desktop, IDEs, other
agents).

## Prerequisites

- Repository setup ([SETUP.md](../../SETUP.md)), virtual environment active
  (`google-adk` and `mcp` are in `requirements.txt`).
- Node.js with `npx`, for MCP Inspector.
- No API keys: the server does not call a model.

## Run it

1. `cd Module_07_Build_MCP_Server/03_adk_to_mcp_bridge`
2. `npx @modelcontextprotocol/inspector python server.py`
3. Open the URL it prints, click **Connect**, list tools, and call
   `lookup_customer` with `customer_id` = `C-100`. Then try `C-999`.

Without a browser:

```bash
npx @modelcontextprotocol/inspector --cli python server.py \
  --method tools/call --tool-name lookup_customer --tool-arg customer_id=C-100
```

## What to look for

- The `inputSchema` Inspector shows was generated by ADK from
  `customer_id: str`, the same schema Gemini gets when the tool is used
  inside an agent.
- An unknown ID returns `"isError": true` with the tool's own error dict.
  The handler maps the ADK `status` convention onto MCP's error flag, so an
  MCP host can tell a failed call from a successful one.
- The low-level server API in `mcp` 2.x registers handlers in the
  constructor: `Server(name, on_list_tools=..., on_call_tool=...)`. Each
  handler receives `(ctx, params)` and returns a result object. The 1.x
  decorators `@server.list_tools()` and `@server.call_tool()` were removed.

When to bridge instead of rewriting in FastMCP:

- One source of truth: a fix in the function reaches both consumers.
- Tools that already pass your ADK evaluations do not need a second
  implementation.
- You choose tool by tool what to publish.

The limit: there is no ADK session behind an MCP call, so `tool_context` is
`None`. Tools that read or write session state, artifacts, or auth through
`ToolContext` need a FastMCP rewrite or a full agent behind the server. To
publish an entire agent (its tools, instruction, and model) as one MCP tool,
ADK has `google.adk.tools.mcp_tool.to_mcp_server(agent)`, currently
experimental; it returns a FastMCP server you run with the transport of your
choice.
